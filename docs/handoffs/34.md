8. 关键教训（承 30–33.md，本会话新增 L10/L11）
L1 STOP-DOCS：预览 md5 == 写入 md5、等显式 go 才 cp
L6：GATE 行为自测主体必 CC，须核 prompt 来源（落 ● Bash 工具块、非 Iris shell prompt；Iris shell 对闸假绿）
L7：见「闸该拦没拦」先分清执行主体，勿把 Iris-shell 假绿读成红线事故
L8：假绿 commit —— nothing to commit / Everything up-to-date 不是成功、是「add 错文件（多半误 add 已入库旧文件）」的红旗；「done」类自报须四样 raw 坐实：git diff --cached --stat 非空且 scope 匹配 → [main <sha>] → push <old>..<new>。本会话 ce3204f / aec6bd8 两 commit 均四样坐实
L9：GATE-1 = PreToolUse 预检 string-match（含 git-write 关键字的整块在执行前即被 deny）；读类命令（git status）可吐 footer 而不触发 deny，勿误读为 bypass
L10（新）：dormant ≠ 可改。文件可能被 md5/snapshot 测字节冻结（如 ce9）。标记/删除前须加一步「查守卫」（grep snapshot/md5/baseline/read_bytes 类测），不只查 import 图。本轮 recon 查了 import、漏查字节守卫，落盘才撞 ce9
L11（新）：commit msg 含括号/斜杠/特殊字符，须 git commit -m "..." 整条、message 在双引号内；裸贴入终端会被 shell 解析炸（syntax error）。复核方给 commit 指令时附完整带引号命令，勿只给 message 文本
