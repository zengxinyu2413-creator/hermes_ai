## §3 段 A 终态(已完全收口)

### 3.1 确定性通过
- start→`is_running=True`→`_connect` 后台任务调度→stop→2 task 在 `asyncio.wait(timeout=10)` 内 **2 done / 0 still**→`is_running=False`→**POST-STOP lingering=0**,全程**零发单**,exit_code=0。
- teardown 用 `asyncio.wait` 确定性等待 task 完成(非 sleep 猜),扎实达成。
- `_ws_snap` 已改读 §3.1 四属性,按权重:**主判据 `_client` / `_stream_client`**(None→非 None = WS 物理已连);**辅判据 `_keepalive_task` / `is_authenticated`**(`is_authenticated` 仅表认证 ≠ 物理连接,降为辅,勿当主判据)。
- **verdict 盲区已关闭并经实战验证**:`verdict = CLEAN iff (exit_code==0 and not lingering and ws_primary_ok)`;`ws_primary_ok` 默认 False(保守),PRE-STOP 权威判定点显式读主判据,`None/<no attr>/<no ws_obj>` 三种都算 False。主判据用 OR(任一非 None 即算已连,容时序差)。本次跑中 verdict 如实报 `SEE ABOVE`(因 WS 未连),证明逻辑有效。

### 3.2 WS 未连的原因已查实 = A(慢),非 B(失败)
PRE-STOP `_connect` 任务诊断段实证:
```
[_CONNECT] '_connect' coro=BinanceCommonExecutionClient._connect  done=False  → 指向 A(连接慢,5s 内未完成)
```
`_connect` 在 IDLE 5s 后**仍 running**(未结束、未抛异常、未取消),故主辅判据全 None 不是连接失败,是 `_connect` 全链路(HTTP instrument_provider 初始化 → account state 拉取 → 才到 WS connect)5s 没跑完。

> **观察(记入档案)**:testnet 下 `_connect` 全链路 >5s。生产/测试给连接时间时需考虑。

## §4 段 B 起手第一步(接手者从这里开始,走两段式)

**新建脚本** `experiments/m3_probe/wp5_segment_b_msgbus.py`(不改段 A 脚本)。目标:start exec_client → 挂 msgbus 监听 → 给足 IDLE 让 `_connect` 跑完 → 看 msgbus 上是否收到 WS 推送的真实消息 → stop 干净收口。

判据优先级:
- **主判据 = msgbus 收到 WS 消息**(直接证据,§2)。收到 = WS 真活。
- **辅判据 = §3.1 四属性翻转**(滞后可能,仅旁证)。

起手要点(供新会话规划,具体实现在新会话两段式推进):
1. **挂 msgbus 监听**:用 NautilusTrader 的 msgbus 订阅/spy 机制捕获 exec_client 经 WS 收到并发布的消息,记录消息类型/数量(尤其 executionReport 回路)。**只读捕获,不回发、不下单。**
2. **IDLE 给足**:基于 §3.2,5s 不够。起手设一个明显够大的值(如 30s)让 `_connect` 全链路跑完;若仍收不到消息再排查,不要在 5s 上反复试。
3. **零发单红线不变**:段 B 是观察 WS 入站消息,**绝不 submit/cancel/new_order**。脚本里 grep 确认这些动作词零命中。
4. **stop 干净收口**:复用段 A 已验证的 `asyncio.wait(timeout=10)` teardown 模式,确保 lingering=0。
5. **base_url testnet 硬断言**:照搬段 A 的 fail-closed 断言。

走两段式:写脚本 → sed 整段回传 + py_compile + grep 动作词零命中 → 主理人核(此脚本会 start/connect,**全核,不进白名单**)→ 放行单独跑。

> **判读纪律**:跑完若 msgbus 收到消息 → WS 实证为活,段 B 主目标达成。若没收到,先确认 `_connect` 是否 `done=True`(给足 IDLE 后应 done);若 done 仍无消息,才是真问题(订阅未挂上 / WS 未推 / 消息被别处消费),逐一查 —— 不要默认"再调大 IDLE"。
