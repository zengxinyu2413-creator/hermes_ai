## §2 安全事故 + 血泪沉淀（本轮重点）
### token 一度混入 .env.example（已闭合）
- 事故：Iris 手敲 .env 时，真 token/chat_id 一度被追加进 .env.example（git 追踪文件，但仅工作树 M、从未 staged/commit/push）。
- 暴露面：CC 的 LMV7-b 探针 `git diff .env.example` 把两行真值打进了终端 + 对话上下文 → token 在该链上已非秘密。
- 处置：① 旧 token 经 @BotFather revoke 作废、生成新 token；② 新 token 写入 .env；③ .env.example 恢复空占位（git diff 空）；④ chat_id 未动（非秘密）。远程仓库始终干净（从未 commit）。
- 根因：.env.example（入库模板，占位符）与 .env（真值容器，gitignore）职责必须严格分离，真 secret 绝不进 .env.example。

### 方法论沉淀
- secret 泄漏靠 revoke 而非改文件：token 一旦在终端/对话露过，删文件无用，唯一彻底处置是轮换作废旧 token。文件恢复是次要。
- raw 胜口头判断（再验）：Iris 一度口头判"没把真 token 写进 .env.example"，但 CC 的 git diff raw 打出真值两行 -> 按 raw（已泄漏）处置，不按口头（没写）处置。承本项目 raw-over-verdict 铁律，secret 场景尤甚——宁可误判已泄漏而轮换，不可误判未泄漏而留患。
- LMV7-b 探针正向价值：「diff .env.example 确认无 secret」这条探针抓出了泄漏，否则两行真值会一直躺工作树，哪天 git add . 即入库。差异坐实型探针的防御价值。
- 验证用一次性 harness 而非跑常驻入口：__main__ 是无限阻塞循环，验证不干净；/tmp harness 调单次 poll_once() 可控零残留（承 P4b）。
- timeout 退出码 != 进程退出码（LMV5 教训）：首版 LMV5 用 timeout --signal=TERM 5，RC=124 是 timeout 自身超时杀，不是 python 进程响应 SIGTERM 的真退出码 —— 这个 verdict 不成立。改手动 bg + kill -TERM + wait 拿真 RC=0 才坐实优雅停。CC 一度把 RC=124 判 True，复核方据语义驳回重验。
