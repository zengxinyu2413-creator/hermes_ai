### 3.3 关键技术点(WP-5/6/7 直接复用)

- **public HTTP 调用无需凭证**:`get_cached_binance_http_client(..., api_key=None, api_secret=None, ...)` 即可
- **HTTP client 是单例缓存**:相同参数返回同一实例。WP-5/6/7 共享一个 client,改参数会绕过 cache
- **nautilus filter schema 是 msgspec.Struct,不是 pydantic**:无 `.model_dump()`,用 `msgspec.structs.asdict()` 或直接 repr
- **filter 字段全 Optional**:`BinanceSymbolFilter` 是 union struct,每个 filter type 只有少数字段非 None。**判别 type 用 `filter.filterType`**(`BinanceSymbolFilterType` enum)
- **`get_http_base_url` 是自动路由**:不用手写 URL 字符串,传 `(account_type, BinanceEnvironment.TESTNET, is_us=False)` 即可
- **clock skew ~80ms**:trading-tokyo-01 ↔ Binance testnet,完全在 recv_window 5000ms 范围内

这条比"再让执行会话 sed 一次"快也稳。

### 4.3 bash `${PIPESTATUS}` 只对上一条命令有效 — **新增**
错误模板(本会话踩过):
```bash
python ... | tee report.txt
echo "---" >> report.txt              # ← 这一句把 PIPESTATUS 覆盖了
echo "exit=${PIPESTATUS[0]}" >> ...   # ← 这里取到的是 echo 的 exit,不是 python 的
```
正确模板:
```bash
python ... | tee report.txt
EXITCODE=${PIPESTATUS[0]}             # ← 紧跟上一行,立刻存到变量
echo "---" >> report.txt
echo "exit=${EXITCODE}" >> ...        # ← 用变量,不会被覆盖
```

### 4.4 VERIFY 指纹应基于不变量,不是阈值 — **新增**
本会话 step 1a 设计 VERIFY 3 用 "symbol 数量 < 500" 做 testnet 指纹 — 失败,因为 2026 testnet 有 1405 个 symbol(数量随时间增长)。改成"非 ASCII symbol 存在性"成功(中文测试币是 testnet **不变特征**,主网绝不会出现)。

**通则**:验证规则应该基于业务上不变的事实(URL 字符串、enum 值、非 ASCII 字符存在性),不是依赖第三方变化的状态(symbol 数量、价格、流动性深度)。

### 4.5 fail-closed 设计的边界 — **新增**
"宁可错杀不打主网"是好原则,但只对"决定性证据"成立。VERIFY 1(base_url 字符串)是决定性的,fail-closed 合理。VERIFY 3 是辅助指纹,fail-closed 反而把脚本卡死跑不完。**主防线 fail-closed,辅助层 informational + WARN** 是更稳的模式。

### 4.6 验证强度按风险分级(沿用第十份 §4.4,加强一次)

### 7.1 WP-6 目标(精度核心)

实现一个**纯计算模块**,把"raw price/quantity"按交易所 filter 规则 floor 到合规值,并校验 minNotional。**不碰网络、不碰 client、不碰凭证、不碰订单提交。**

### 7.2 接口规格(草案,可调)

```python
from decimal import Decimal
from dataclasses import dataclass

@dataclass(frozen=True)
class InstrumentLimits:
    """Subset of Binance filters relevant to order precision."""
    price_tick: Decimal       # PRICE_FILTER.tickSize
    price_min: Decimal        # PRICE_FILTER.minPrice
    price_max: Decimal        # PRICE_FILTER.maxPrice
    qty_step: Decimal         # LOT_SIZE.stepSize
    qty_min: Decimal          # LOT_SIZE.minQty
    qty_max: Decimal          # LOT_SIZE.maxQty
    min_notional: Decimal     # NOTIONAL.minNotional
    apply_min_to_market: bool # NOTIONAL.applyMinToMarket

def floor_to_tick(raw: Decimal, tick: Decimal) -> Decimal: ...
def floor_to_step(raw: Decimal, step: Decimal) -> Decimal: ...

def round_price(raw_price: Decimal, limits: InstrumentLimits) -> Decimal:
    """Floor price to tick, validate price_min/price_max."""

def round_quantity(raw_qty: Decimal, limits: InstrumentLimits) -> Decimal:
    """Floor qty to step, validate qty_min/qty_max."""

def check_notional(
    price: Decimal,
    qty: Decimal,
    limits: InstrumentLimits,
    is_market_order: bool,
) -> bool:
    """qty * price >= min_notional (if applicable)."""

@dataclass(frozen=True)
class OrderSpec:
    price: Decimal      # rounded
    quantity: Decimal   # rounded
    is_market: bool

class OrderRejected(Exception): ...

def build_order_spec(
    raw_price: Decimal,
    raw_qty: Decimal,
    limits: InstrumentLimits,
    is_market: bool,
) -> OrderSpec:
    """Top-level: floor + validate + return OrderSpec or raise OrderRejected."""
```

### 7.3 红线(主控表 §4 WP-6 DoD 钉死的)

1. **全程 Decimal**,任何 `float` 出现在 price/qty 计算路径**都是 bug**
2. **floor 取整,不四舍五入**:
```python
   floor_to_tick(Decimal("123.456"), Decimal("0.01")) == Decimal("123.45")  # 不是 123.46
```
3. **解析 filter 时从 str 转 Decimal**,直接 `Decimal("0.00100000")`,不要先 float 再 Decimal
4. **minNotional 计算精确**:`qty * price` 用 Decimal 乘法,与 `min_notional` Decimal 比较
5. **拒单显式**:不能 floor 到合规值时抛 `OrderRejected`(说明原 raw 值过小、过大、或 notional 不足),**不要静默返回 None 或 0**
6. **不调用任何网络函数**;`InstrumentLimits` 由调用方(WP-5 实例化时)从 nautilus instrument 提供 — WP-6 自己**不解析 exchangeInfo**
7. **WP-6 文件外没有任何写改动**(不动 risk/、不动 strategies/、不动 adapters/)

### 7.4 单测覆盖(全部必写,主控表 §4 钉死)

参考 step 1a 实测的 SOLUSDT 数据(`tickSize=0.01`、`stepSize=0.001`、`minNotional=5`),构造覆盖:

- **floor 正确性**:`floor_to_tick(0.123, 0.01) = 0.12`,`floor_to_step(1.2345, 0.001) = 1.234`
- **边界**:raw 刚好压 tick(`0.01 floor 0.01 = 0.01`)、压 minQty、压 maxQty、压 minPrice、压 maxPrice
- **拒单**:raw_qty < qty_min → raise;floor 后 qty * price < min_notional → raise;raw > max → raise
- **市价单**:`apply_min_to_market=True` 时市价也兜 minNotional;`False` 时不兜
- **Decimal 精度**:`Decimal("0.1") + Decimal("0.2") == Decimal("0.3")`(确保没用 float)
- **零步长**:`step=0` 应该 raise ValueError 或类似(MARKET_LOT_SIZE 真有 stepSize=0,边界要处理)
- **极端值**:超大 raw_qty 触发 maxQty;超小 raw_price 触发 minPrice
