## 4. 流程教训（本会话新增，防再犯）

### L1 -- 「签 PHASE1」不等于「go cp」（STOP-DOCS 写闸）

STOP-DOCS 正确顺序：预览 CLEAN -> 复核方签 PHASE1 -> **主理人 chat 里显式 go** -> 才 cp 推正。
本会话在 SS6.8.1-G3 落档时，用户签「PHASE1」后 CC 立即执行了 cp，跳过「等显式 go」。
**硬规矩**：「签 PHASE1」= 审核通过；「go」= 推正授权。两者不同义，不可合并。
CC 必须在收到显式 go 之后才 cp，不得以「PHASE1 已签」自动放行。

### L2 -- 日文字形笔误（简体汉字被日文同形替换）

本会话两次把「发单」中的汉字误写成外观相近的日文字形（U+767A / U+5358），
均在写入 /tmp 块文件时发生，被写前 BADCHAR 探针拦截，未入真文件。
**防呆**：凡含「发单 / 发令 / 单量」等词的落档，写后必跑 BADCHAR 探针（计数预期 0）。
本会话两次均靠探针兜底，未污染 CLAUDE.md 或 docs/handoffs/。
