### 4.3 ⭐ 真因铁证坐实（核心，新会话据此修）

**根因：ExecClient 的 `_connect()` 加载 instrument 进 provider，但从不 push 进 cache；RiskEngine 查的是 cache → 永远 miss。**

源码两条路径对比（CC recon 坐实）：
| 客户端 | `_connect()` | instrument 进 cache? |
|---|---|---|
| **DataClient**（data.py L247-249） | initialize() → **`_send_all_instruments_to_data_engine()`** → 推 cache | ✅ |
| **ExecClient**（execution.py L344-360） | initialize() 加载进 provider，**无 push cache 步骤** | ❌ |

- RiskEngine（engine.pyx L443）：`instrument = self._cache.instrument(order.instrument_id); if instrument is None: deny`
- cli.py 只配了 exec_clients、**没配 data_clients** → cache 永远空
- **⚠️ 上一轮 cli.py 加的 `instrument_provider=BinanceInstrumentProviderConfig(load_ids=...)` 对 ExecClient 无效**（instrument 加载进 provider 但不进 cache）。07:30 raw 实测：`Loaded 1 instruments` 后仍 DENIED，铁证。
- **CC 两次误判**（说"时序保证 cache 有 instrument""修复完整""不需检查"）均被 raw 推翻——FALSIFY-CLEAN 边缘，新会话拿 raw 对每个 CC 结论

### 4.4 修复路径裁定 = 路径 C（复核方已定）

| 路径 | 做法 | 裁定 |
|---|---|---|
| A：加 DataClient（BinanceDataClientConfig） | 会额外连 WS 订阅行情流 | ❌ 杀鸡用牛刀，one-shot 不需行情 |
| B：strategy request_instrument 回调 | 异步请求+回调下单 | △ 走 DataClient 通道，无 DataClient 时未必可用 |
| **C：build() 后 run() 前手动 `node.cache.add_instrument()`** | cli.py 已在拉 exchangeInfo → 构造 NT Instrument → 注入 cache | ✅ **选定** |

**选 C 理由**：cli.py 本就已拉 exchangeInfo（J2 precision 那段 `httpx.get(.../exchangeInfo)` + `_parse_instrument_limits`），数据在手，只差构造成 NT Instrument 塞进 cache；不需 DataClient、不订阅行情、不改 strategy 异步逻辑；最契合 one-shot。
