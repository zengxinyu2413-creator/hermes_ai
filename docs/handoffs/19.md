**v1 退化根因分析**:
- L1 run 的 lingering=0 是因为先调 `exec_engine.stop()` → `_on_stop()` 发 sentinel → cmd/evt queue task 看到 sentinel 自然 break loop → 然后 kill 再 cancel 已经在退出过程中的 task → 真正 done

**教训**:NT API 设计的"二选一"分析正确,但**调用方需要补齐 await 完成**,不能依赖 NT 调用方法本身同步保证 task done。这是异步框架的常识坑,我在第一次推方案时没标出来。
