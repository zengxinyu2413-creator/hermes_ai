## §3 方法论沉淀（本轮新）

- **多次诚实 STOP = self-advancing 的对立面**：本轮 CC 在 ① CBP3 filter 漂移、② floor 撞 PERCENT_PRICE、③ 探针无传参、④ §4.1 不代跑、⑤ triage 不把「内容已给」当 STOP-DOCS 放行——每次都不擅进/不擅缩、raw 列裸事实交裁。§6.1 反放水正向典范集。
- **§4.1 STOP-B 是结构归属（WHO）非授权门**：Web Claude 误把「STOP-B 已授权」写成「CC 提交真单」，CC 逐字读 live `CLAUDE.md §4.1` 纠正——真下单只由主理人手敲，GATE-3 物理后挡，聊天措辞不开口子。复核方出题也会错，执行方读 live 治理文件是后挡（与 git 写权同构）。
- **真 testnet 验逮离线对拍逮不到的活体边界**：F' 离线对拍 12 字段全等，但 `PERCENT_PRICE_BY_SIDE` 的 bidMultiplierDown 是相对活体市价的乘数，离线固化逮不到；真验时 `floor(avg×0.5)` 正压下界被拒——这正是 P4b 存在的价值：**离线证明 ≠ 真 venue 受理**。
- **副本调派生 ≠ 塞定值**：CBP8 防绕路的关键——提交值必须提交时现场经 F' 真函数算，而非上游抄来的定值。三跑市价 64.83/64.90/64.96 互异坐实现算。塞定值会把「F' 派生的精度被接受」偷换成「某个数被接受」，断证链。
- **api_key=None 取 instrument = 生产 live 路同款**：line182 修复意外坐实——副本修后取 instrument 方式与 cli 真 live 注入路径（路径C）一致，CBP8 不破反更贴生产。testnet 不支持 SAPI 费率端点 → 带凭据 provider 静默空载，是隐蔽坑。
- **双源 requery 胜单次自报**：CC triage 不引用 run2 自报的 balance_after，独立 requery 当前状态坐实冻结已释放、时序滞后非残留——raw 双源胜单次快照（承「raw 胜 verdict」）。
